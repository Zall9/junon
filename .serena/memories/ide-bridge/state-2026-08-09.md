# IDE Bridge — state of play, end of 9 Aug 2026

Supersedes everything earlier. Read `docs/STATUS.md` for the full picture; this is the orientation.

## Where it stands

- **16 routed methods.** JetBrains serves all 16. VS Code serves 13 — the three it does not
  (`workspace/undo`, `workspace/searchTodos`, `workspace/listBookmarks`) are **principled refusals**,
  not gaps: VS Code has no scoped undo, no TODO index, no bookmarks of its own.
- **Four JetBrains IDEs actually run**, not merely measured Compatible: IntelliJ IC-2025.2,
  PhpStorm PS-253, GoLand GO-261, PyCharm PY-262. Each does symbols → semantic rename → apply →
  undo, and PhpStorm/GoLand/PyCharm each applied a real quick fix.
- **411 TypeScript tests, 194 Kotlin, 50 conformance, 8 VS Code host scenarios.** Internal API
  surface baselined at two symbols, both in `IntelliJDiagnostics`, both for reading diagnostics.
- **Nothing is committed.** Everything is in the working tree, per AGENTS.md.

## The design rule, now observed rather than argued

No language-specific code in the JetBrains adapter. Four IDEs produced four entirely different
`declarationType` vocabularies — `CLASS`/`METHOD`, `CLASS_METHOD`/`CLASS_FIELD`,
`TYPE_SPEC`/`METHOD_DECLARATION`, `Py:CLASS_DECLARATION`/`Py:TARGET_EXPRESSION` — with the adapter
branching on none of them. A fifth IDE needs no work. See `mem:ide-bridge/kind-and-discriminator`.

## Boundaries that are measured, not assumed

- **Structural refactorings are refused by name** (`extractMethod`, `inline`, `move`,
  `changeSignature`). The platform's only language-neutral route is a dialog-driven
  `RefactoringActionHandler`, which cannot run behind a socket. ADR-0028 records the three rejected
  alternatives.
- **`supertypes` is refused on JetBrains, served on VS Code.** Each adapter serves what its IDE can;
  the protocol does not level both down.
- **VS Code publishes diagnostics only for *visible* documents.** Measured: `openTextDocument` leaves
  the document tracked and still yields nothing; a code-action pull returns only `refactor.*`, never
  a `quickfix`. So the JetBrains approach (open an editor without focus, run the analyser) has no VS
  Code equivalent, and the VS Code quick-fix path has **no real-host verification**.

## What this session's failures taught

See `mem:ide-bridge/verification-method` — it carries the lessons, and they are worth reading before

## Deferred by explicit decision

Run configurations, debugger, terminal, VCS. When taken up they need an **enumerated** surface —
"start the existing configuration named X", never "run this".

Noted for later by the user: a **completion method** (the protocol never asks for completions, which
is the most visible thing a language plugin provides), and **third-party plugin verification**
(everything is measured against bundled language support only).

## Working constraints (AGENTS.md, still in force)

Never commit, push, or touch a remote. Do not modify `TASK.md` or `.idea/`. Loopback only. Never log
secrets or file contents. Never describe a textual edit as semantic. Never declare a feature complete
without running its tests.
