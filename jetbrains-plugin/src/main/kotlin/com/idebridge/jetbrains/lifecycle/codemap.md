# jetbrains-plugin/src/main/kotlin/com/idebridge/jetbrains/lifecycle/

## Responsibility

IntelliJ Platform lifecycle hooks that bridge IDE startup/shutdown and project open/close events into IDE Bridge daemon connection management. Three thin listeners wire platform events to the service layer: `BridgeStartupActivity` handles project open (connect), `ApplicationLifecycleListener` handles app shutdown (disconnect), and `ProjectLifecycleListener` handles project close (**releases that project's link** — ADR-0033). A fourth type, `OpenProjectsListener`, is a message topic — not a lifecycle hook — that the two open/close hooks announce on so the tool window can rebuild its row list when the set of open projects changes, independently of link changes. All types are registered declaratively in `plugin.xml` and delegate all work to services in the `service/` package. They contain no business logic and read/write no data themselves.

## Design Patterns
- **`ProjectActivity` (suspend, off-EDT)**: `BridgeStartupActivity` implements `ProjectActivity` (BridgeStartupActivity.kt:21), the platform's supported replacement for the deprecated `ProjectManagerListener.projectOpened` and `@ApiStatus.Internal` `AppLifecycleListener.appStarted`. It is `suspend` and runs off the EDT by construction, so no explicit pooled-thread hop is needed (unlike the old `executeOnPooledThread` pattern).
- **Listener / Topic Registration**: `ApplicationLifecycleListener` implements `AppLifecycleListener` and `ProjectLifecycleListener` implements `ProjectManagerListener`. Both are registered via `<applicationListeners>` / `<projectListeners>` XML in `plugin.xml`, not programmatically. `OpenProjectsListener` is a `fun interface` used as a `Topic` on the application message bus — subscribers connect via `messageBus.connect().subscribe(OpenProjectsListener.TOPIC, ...)` (not registered in XML).
- **Delegation to Services**: Listeners contain no business logic. They call `BridgeDaemonConnectionService.getInstance()`, `ReadinessManager.getInstance()` — the services hold state and behavior.
- **A link per project**: `BridgeStartupActivity` runs per project and links that project. It used to rely on `connect()` being "idempotent", which in practice meant the second project opened was silently ignored because one application-wide flag was already set — measured in a real IDE, 2026-08-10 (ADR-0033). Each project now has its own session, and `link` reports `Linked`, `AlreadyLinked` or `Refused(reason)`.

## Key Types
- `BridgeStartupActivity` (BridgeStartupActivity.kt:21) — `class : ProjectActivity`. Project-open hook. Holds a `logger` (line 23). Public API replacement for deprecated `projectOpened` / internal `appStarted`. Calls `OpenProjectsListener.announce()` after linking (line 41).
- `ApplicationLifecycleListener` (ApplicationLifecycleListener.kt:14) — `class : AppLifecycleListener`. App-level shutdown hook. Holds a `logger` (line 16). Only `appClosing()` remains; `appStarted` removed because it is `@ApiStatus.Internal`.
- `ProjectLifecycleListener` (ProjectLifecycleListener.kt:15) — `class : ProjectManagerListener`. Project-level close hook. Holds a `logger` (line 17). Only `projectClosing()` remains; `projectOpened` removed because it is deprecated for removal and replaced by `BridgeStartupActivity`. Calls `OpenProjectsListener.announce()` after unlinking (line 33).
- `OpenProjectsListener` (OpenProjectsListener.kt:23) — `fun interface` with one method `openProjectsChanged()`. Announced when the set of open projects changes. Application-level (`@Topic.AppLevel`), non-broadcasting (`Topic.BroadcastDirection.NONE`, line 32) — every open project's panel is a subscriber, and each reads the whole set for itself. The platform states the change in two places — opening arrives as a `ProjectActivity` (`BridgeStartupActivity`), closing stays a `ProjectManagerListener` (`ProjectLifecycleListener`) — and this topic is where they meet. A subscriber gets one topic instead of reproducing the split.

## Key Functions
- `BridgeStartupActivity.execute(project: Project)` (BridgeStartupActivity.kt:32) — Logs project open (line 33), sets `ReadinessManager` to `INITIALIZING` (line 34), calls `BridgeDaemonConnectionService.getInstance().link(project)` and logs a refusal with its reason (lines 36-38). Announces on `OpenProjectsListener` whatever the outcome (line 41): every already-open project's panel offers a row per open project, and a project that opened and was refused a link still belongs in that list. Runs off the EDT by construction (suspend function).
- `ApplicationLifecycleListener.appClosing()` (ApplicationLifecycleListener.kt:18) — Logs shutdown (line 19), calls `BridgeDaemonConnectionService.getInstance().disconnectAll()` — every link, since there is one per project. Safe from any thread.
- `ProjectLifecycleListener.projectClosing(project: Project)` (ProjectLifecycleListener.kt:28) — Logs project close (line 29), then calls `BridgeDaemonConnectionService.getInstance().unlink(project)` (line 30). Announces on `OpenProjectsListener` (line 33): the other windows' panels list this project too, and unlinking alone does not tell them it is going away — a project closing while it was never linked changes no link at all. This is the half that was missing: the old call went to a Phase 0 skeleton whose `unregisterWorkspace()` only logged, so nothing was released and the connection went on believing it was live (ADR-0033). Readiness is now derived from the link map rather than set here.
- `OpenProjectsListener.announce()` (OpenProjectsListener.kt:42-46) — Publishes `openProjectsChanged()` on the application message bus. Silent when the application is disposed (line 44): a project also closes while the IDE itself is shutting down, and by then the bus may already be gone — an announcement nobody can hear is not worth an error in the log.

## Data & Control Flow
1. **Project open**: IntelliJ fires `ProjectActivity` → `BridgeStartupActivity.execute()` (off EDT) → `ReadinessManager.setState(INITIALIZING)` → `BridgeDaemonConnectionService.link()` → `OpenProjectsListener.announce()` → every panel's `refresh()` rebuilds its row list.
2. **Project close**: IntelliJ fires `projectClosing` → `ProjectLifecycleListener` → `BridgeDaemonConnectionService.unlink(project)` → `OpenProjectsListener.announce()` → every panel's `refresh()` rebuilds its row list.
3. **App shutdown**: IntelliJ fires `appClosing` → `ApplicationLifecycleListener` → `BridgeDaemonConnectionService.disconnectAll()`.

No data is read or written by the listeners themselves — they are pure control-flow routers. `OpenProjectsListener` carries no payload: subscribers re-read `ProjectManager.getInstance().openProjects` themselves.

## Integration Points
- **Consumed by**: IntelliJ Platform container — instantiates and invokes listeners based on `plugin.xml` `<applicationListeners>` and `<projectListeners>` declarations; `BridgeStartupActivity` is registered as a `<postStartupActivity>` or via `ProjectActivity` extension point. `OpenProjectsListener.TOPIC` is consumed by `com.idebridge.jetbrains.ui.BridgeToolWindowFactory` (subscribed in `BridgePanel.init`).
- **Depends on**: `com.idebridge.jetbrains.service.BridgeDaemonConnectionService`, `com.idebridge.jetbrains.service.ReadinessManager`. IntelliJ Platform APIs: `ProjectActivity` (suspend), `AppLifecycleListener`, `ProjectManagerListener`, `Project`, `ApplicationManager`, `Topic`, `logger<T>()`.
- **External boundaries**: None directly. All I/O and network behavior is in the service layer.

## Common Gotchas
- **`ProjectActivity.execute()` is `suspend` and off-EDT by construction** — No `executeOnPooledThread` wrapper is needed, unlike the old `appStarted` listener (BridgeStartupActivity.kt:17-19 comment).
- **`appStarted` was removed because it is `@ApiStatus.Internal`** — The Plugin Verifier rejects internal API usage. `appClosing` is public API and has no equivalent elsewhere, so it stays (ApplicationLifecycleListener.kt:8-13 comment).
- **`projectOpened` was removed because it is deprecated for removal** — `ProjectActivity` is the platform's supported replacement and is the only one of the three that is public API (BridgeStartupActivity.kt:13-16 comment).
- **`projectClosing` is not deprecated** — Cancelling in-flight work for a closing project (AGENTS.md §3) has no supported alternative, so `ProjectLifecycleListener` stays. `projectClosing` runs on the EDT — `unlink(project)` must remain safe to call from EDT (see BridgeDaemonConnectionService contract).
- **Link is per project** — `BridgeStartupActivity` runs per project, not once per application. Multiple projects opening will call `link()` multiple times. This is safe by design (BridgeStartupActivity.kt:19).
- **`OpenProjectsListener.TOPIC` is app-level and non-broadcasting** — `@Topic.AppLevel` with `BroadcastDirection.NONE` (OpenProjectsListener.kt:30-32). Every open project's panel subscribes independently and reads the whole open-project set for itself.
- **`announce()` is silent when the application is disposed** — A project also closes during IDE shutdown, and the message bus may already be gone. `announce()` checks `application.isDisposed` and returns silently rather than throwing (OpenProjectsListener.kt:43-44).
- **Opening and closing arrive through different platform hooks** — `projectOpened` is deprecated, so opening arrives as a `ProjectActivity` (`BridgeStartupActivity`); `projectClosing` is not deprecated, so closing stays a `ProjectManagerListener` (`ProjectLifecycleListener`). `OpenProjectsListener` unifies the two so subscribers see one signal (OpenProjectsListener.kt:15-18 comment).
- **`ProjectManagerListener` deprecation** — The class itself is deprecated in IntelliJ 2025.2 but `projectClosing` remains the supported topic. The old `@Suppress("DEPRECATION", "OVERRIDE_DEPRECATION")` annotation is no longer present in the current code; verify if needed after platform upgrades.
