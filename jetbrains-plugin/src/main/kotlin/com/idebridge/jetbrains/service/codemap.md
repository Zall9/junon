# jetbrains-plugin/src/main/kotlin/com/idebridge/jetbrains/service/

## Responsibility

Application- and project-level IntelliJ services that manage daemon connection state, IDE readiness tracking, and workspace registration — and the production backend that answers all 19 routed daemon requests. The service layer is fully wired (Phase 4 complete): `AdapterBackend` is the central production handler implementing `AdapterRouter.Backend`, `BridgeDaemonConnectionService` owns **one session per linked project** (discovery → transport → handshake → registration → serving), keyed by `Project`, and `ReadinessManager` maps JetBrains dumb/smart mode to IDEBP readiness states. `IndexHealthNotifier` is a stateless `object` that warns the person in the IDE when a symbol search cannot answer because a project has no indexed source root (ADR-0034) — the one condition the wire carries but the only party who can fix it never sees.

## Design Patterns
- **IntelliJ Service Pattern**: `BridgeDaemonConnectionService` and `ReadinessManager` are `@Service(Service.Level.APP)` (singleton per application). Both are retrieved via `getInstance()` companion-object statics rather than constructor injection. Auto-discovered by IntelliJ Platform 2025.2 — no XML registration in `plugin.xml` (plugin.xml:28-36). `AdapterBackend` is not a service: it is constructed by `BridgeDaemonConnectionService` with the project, workspace, and session context.
- **Backend Interface Implementation**: `AdapterBackend` implements `AdapterRouter.Backend` (AdapterBackend.kt:89). Every routed method delegates to platform layer objects (`IntelliJNavigation`, `IntelliJRename`, `IntelliJDiagnostics`, `PsiSymbols`, etc.) inside a `ReadAction`. Mutations go through `IntelliJEditScheduler.runWrite`.
- **Once per project, only for what a person can act on**: `IndexHealthNotifier` warns about a missing source root at most once per project per session (IndexHealthNotifier.kt:54). Indexing finishes by itself, so it is reported on the wire and not as a balloon; a missing source root does not, so it is. Repeating either on every search would train the user to dismiss them.
- **A map of links, not a flag**: the connection service holds `ConcurrentHashMap<Project, Link>`. The single `@Volatile connected` flag it replaced was released only at IDE shutdown, so closing a project left a dead session that looked live and no later project could register — measured in a real IDE, 2026-08-10 (ADR-0033). `ReadinessManager` keeps its `@Volatile` field.
- **kotlinx.serialization**: Used by the symbol kind mapper's serializer descriptor (see `symbol/` package).
- **Enum State Machine**: `ReadinessState` models the five IDEBP readiness states (TASK.md §13). `isIndexReady()` gates index-dependent capabilities.
- **Serving on a Dedicated Thread**: `BridgeDaemonConnectionService` spawns a daemon thread (`"idebp-adapter-serve"`, `isDaemon = true`, `:177`) to run `RpcClient.serve()`, so the dispatch thread stays free — an edit needs the EDT, and an adapter that occupied it while waiting on its own edit would deadlock.

- `IndexHealthNotifier` (IndexHealthNotifier.kt:27) — `object`. The `forget(project: Project)` method (`:78-80`) removes a project from the `warned` set — called on `unlink` so a project that is fixed and linked again is warned again if it was not fixed after all.

## Key Functions
- `BridgeDaemonConnectionService.link(project: Project): Outcome` (`:123-209`) — Full lifecycle for one project: reads discovery file (`DiscoveryReader.read`), captures the snapshot (`IntelliJProjectSnapshot.capture`), connects transport (`WebSocketTransport.connect`), handshakes (`HandshakeClient.connect`), starts `DaemonAnalysisTracker`, constructs `AdapterBackend`, creates `RpcClient` with `AdapterRouter(backend)`, registers via `AdapterRegistration.register`, spawns the serving thread, records the link and refreshes readiness. Idempotent — a project already linked reports `AlreadyLinked(workspaceId)`. Returns a typed `Refused(reason)` rather than throwing when no daemon is running — an IDE without a bridge is the normal case. **Must be called off the EDT.** The serving thread is a daemon thread (`isDaemon = true`, `:185`). `link()` subscribes to `DumbService.DUMB_MODE` (`:192-199`) — announces readiness on dumb/exit dumb mode. Fixes a bug where `workspace/getStatus` answered `initializing` indefinitely while search worked (measured twenty minutes after the IDE settled). Calls `announceReadiness(project)` after `refreshReadiness()` (`:207`).
- `BridgeDaemonConnectionService.warnIfNothingToSearch(project: Project)` (private, `:222-228`) — Called at end of `link()` before `refreshReadiness()`. Deferred to smart mode via `DumbService.runWhenSmart` because a Gradle project has no source root yet at open. Calls `IntelliJProjectSnapshot.hasSourceRoots(project)` and `IndexHealthNotifier.warnNoSourceRoots(project)`.
- `BridgeDaemonConnectionService.unlink(project: Project)` (`:218-230`) — Safe from any thread and for a project never linked. Disconnects the indexing connection (`:221`) before transport close, removes the link, interrupts its serving thread, closes its transport, calls `IndexHealthNotifier.forget(project)` at `:227`, refreshes readiness. Called from `ProjectLifecycleListener.projectClosing`. Forgotten on unlink so a project that is fixed and linked again is warned again if it was not fixed after all.
- `BridgeDaemonConnectionService.disconnectAll()` (`:254-257`) — Releases every link; for application shutdown. Calls `unlink` for each linked project.
- `isLinked(project): Boolean` (`:259`), `workspaceIdOf(project): String?` (`:261`), `linkedProjects(): List<Project>` (`:264`), `daemonAvailable(): Boolean` (`:267`) — what the `IDE Bridge` tool window reads.
- `addChangeListener(listener: () -> Unit)` (`:270-272`) / `removeChangeListener(listener: () -> Unit)` (`:274-276`) — notifies the listener whenever a link appears or disappears.
- `announceReadiness(project)` (private, `:296-311`) — sends `workspace/readinessChanged` notification; state computed fresh each time from `ReadinessModel.status` + `IntelliJProjectSnapshot.indexState`. Failures logged and dropped — a workspace whose status could not be announced is still a workspace that works, and every route already reports its own readiness when asked.
- `refreshReadiness()` (private, `:313-322`) — sets `ReadinessManager` to `DISCONNECTED` when no links, `READY` when any. Notifies all listeners. Derives readiness from the link map so the two can no longer disagree the way they did while the failure was invisible.
- `defaultDiscoveryPath(): Path` (companion, `:334-337`) — `IDE_BRIDGE_DISCOVERY_FILE` env var, or `~/.ide-bridge/discovery.json`.
- `AdapterBackend.documentSymbols(workspaceId, uri): DocumentGetSymbolsResult?` (AdapterBackend.kt:149-171) — Reads PSI file, maps declarations via `PsiSymbols.declarations` + `SymbolMapping.mapDocument`, materializes handles via `handles.materializeDocument`. Returns `null` when `workspaceId` does not match.
- `AdapterBackend.searchSymbols(params): AdapterRouter.SearchOutcome?` (AdapterBackend.kt:173-256) — Checks `IntelliJProjectSnapshot.indexState` first: if not `SMART`, returns `IndexNotReady` (`:180-182`). Then checks `IntelliJProjectSnapshot.hasSourceRoots`; if no source roots, calls `IndexHealthNotifier.warnNoSourceRoots(project)` (`:186-187`) and sets `unindexed=true` which also drives `truncated`. Searches via `IntelliJSymbolSearch.search`, passing `params.kinds?.toSet()` (`:192`) so kind filtering is applied during collection, not after. Maps each hit to a `Draft<PsiAnchor>` with `SymbolKindMapper.classify` + `SymbolMapping.createLocator`, filters by `withinWorkspace`, materializes as transient handles. Uses `PsiSymbols.identifierRange` (`:216`) — same rule `document/getSymbols` reads, so one route cannot deny a declaration the other reports (ADR-0030). The `unrepresentable` flag (`:196, 201, 210, 219, 223, 229`) is set when a hit cannot be **represented** (no file URL, no text range, no identifier anchor, offsets outside the document, no name) and drives `truncated=true`, which ADR-0017 requires and which was previously silent; a hit dropped for **scope** (outside every root) deliberately does not set `truncated`, since scope is not incompleteness (ADR-0032). The `unindexed` flag is OR'd into `truncated` (`:252`) because the workspace holds matches this response cannot carry.
- `AdapterBackend.documentRead(workspaceId, uri): DocumentContent?` (AdapterBackend.kt:258-273) — Reads PSI file text (in-memory document, not disk — an editor with unsaved changes is what the user sees), builds `DocumentModel` content.
- `AdapterBackend.documentRevision(workspaceId, uri): DocumentGetRevisionResult?` (AdapterBackend.kt:275-283) — Calls `documentRead` and drops the text. Computing revision separately would risk reporting a revision that never described any content served.
- `AdapterBackend.diagnostics(workspaceId, documentUris): DiagnosticsGetSnapshotResult?` (AdapterBackend.kt:326-356) — Requests analysis for unopened documents (`requestAnalysis`), reads highlights via `IntelliJDiagnostics.highlights`, maps via `DiagnosticMapping.map` with `DaemonAnalysisTracker.state`.
- `AdapterBackend.prepareRename(params): RenameOutcome?` (AdapterBackend.kt:358-400) — Resolves the symbol handle, prepares via `IntelliJRename.prepare`, builds `EditPlan` with `Guarantee.SEMANTIC`, registers in `plans`.
- `AdapterBackend.locations(method, params): SymbolLocationsResult?` (AdapterBackend.kt:402-430) — Resolves handle, dispatches to `IntelliJNavigation.definition` / `references` / `implementations`, filters by `withinWorkspace`.
- `AdapterBackend.hierarchy(params): HierarchyOutcome?` (AdapterBackend.kt:432-468) — Resolves handle, maps `HierarchyRelation` to `IntelliJHierarchy.Relation`, delegates to `IntelliJHierarchy.of`. `UnsupportedRelation` → `HierarchyOutcome.Unsupported`.
- `AdapterBackend.searchTodos(params): WorkspaceSearchTodosResult?` (AdapterBackend.kt:489-518) — Validates workspaceId, clamps limit to `DEFAULT_SEARCH_LIMIT`/`MAX_SEARCH_LIMIT`. One document when `uri` is set, whole project otherwise. Filters results by `withinWorkspace`. The two cases are separated rather than chained through an elvis: a uri the IDE cannot resolve falling through to the project-wide sweep would answer one missing file with every marker in the repository.
- `AdapterBackend.listBookmarks(params): WorkspaceListBookmarksResult?` (AdapterBackend.kt:520-535) — Validates workspaceId, clamps limit. Delegates to `IntelliJBookmarks.of`, filters by `withinWorkspace`.
- `AdapterBackend.resolveAt(params): SymbolResolveAtResult?` (AdapterBackend.kt:518-548) — Resolves offset, finds declaration at position via `IntelliJNavigation.declarationAt`, materializes transient handles and filters by name.
- `AdapterBackend.prepare(params): RenameOutcome?` (AdapterBackend.kt:558-596) — Dispatches by `EditOperation`: `QUICK_FIX` → `prepareQuickFix`, `REFORMAT`/`OPTIMIZE_IMPORTS` → document edit plan, else `CAPABILITY_UNAVAILABLE`. Builds `EditPlan` with `IntelliJDocumentEdits.guarantee`.
- `AdapterBackend.prepareQuickFix(params): RenameOutcome` (AdapterBackend.kt:606-647) — Resolves the fix id via `IntelliJDiagnostics.resolveFix` (re-derived from current highlights — fails closed if the document changed). Builds `EditPlan` with `Guarantee.SEMANTIC`.
- `AdapterBackend.applyPlan(params): ApplyOutcome?` (AdapterBackend.kt:649-734) — Claims plan from `plans.claim`, reads before-hash, runs mutation via `scheduler.runWrite` (rename → `IntelliJRename.apply`, document → `IntelliJDocumentEdits.apply`, quick fix → re-resolve + `action.invoke`), saves all documents (`:696`), invalidates handles + tracker, returns `ModificationResult` with before/after hashes and undo token. Quick fixes are re-resolved at apply time (`:677-690`).
- `AdapterBackend.undo(params): ApplyOutcome?` (AdapterBackend.kt:736-795) — Validates undo token session, removes token (one use only, `:742-744`), reverts via `IntelliJUndo.undo` on the dispatch thread but **not inside a write command** (`:752-760`) — `UndoManager` opens its own and nesting is rejected by the platform. Commits + saves, invalidates handles + tracker.
- `AdapterBackend.discardPlan(params): WorkspaceDiscardPlanResult?` (AdapterBackend.kt:797-801) — Calls `plans.discard`, returns result with `discarded = refusal == null`.
- `AdapterBackend.requestAnalysis(uris: List<String>)` (AdapterBackend.kt:309-324, private) — Opens editors without focus and restarts the daemon for unopened files, so a file the user never opened is inspected. Does not block on completion (`:300-308`) — the snapshot already reports `pending` truthfully, and an early answer is honest.
- `ReadinessManager.getState(): ReadinessState` (ReadinessManager.kt:44) — Returns current readiness.
- `ReadinessManager.setState(newState: ReadinessState)` (ReadinessManager.kt:46) — Idempotent: only logs and writes if `newState != state` (line 47). Phase 4: emit `workspace/readinessChanged` notifications (line 51 comment).
- `ReadinessManager.isIndexReady(): Boolean` (ReadinessManager.kt:60) — Returns `true` only for `READY` or `DEGRADED`. Index-dependent operations must return `INDEX_NOT_READY` when this is `false` (lines 56-59).

## Data & Control Flow
1. **Daemon connection (full lifecycle)**: `ApplicationLifecycleListener` → `link(project)` on pooled thread → `DiscoveryReader.read(discoveryPath())` → `IntelliJProjectSnapshot.capture(project)` → `WebSocketTransport.connect(endpoint)` → `HandshakeClient.connect(...)` → `DaemonAnalysisTracker(project).start()` → `AdapterBackend(project, workspace, adapterId, sessionId, workspaceEpoch, tracker)` → `RpcClient(socket, AdapterRouter(backend))` → `AdapterRegistration.register(client, workspaces)` → spawn `"idebp-adapter-serve"` daemon thread running `client.serve()` → store `Link` → `refreshReadiness()`.
2. **Inbound request**: Daemon forwards request → `RpcClient.serve()` → `AdapterRouter.handle(method, raw)` → `route()` decodes params → `AdapterBackend.<method>(params)` → `ReadAction.compute { ... }` for reads, `scheduler.runWrite { ... }` for writes → result encoded or refusal mapped to `ErrorCode` → `RpcClient.Answer` sent back.
3. **Readiness transitions**: `ProjectLifecycleListener` → `setState(INITIALIZING)` on project open. Dumb/smart mode listener (`DumbService.DUMB_MODE` subscription in `link()`, `:192-199`) → `announceReadiness(project)` on dumb/exit dumb mode, sending `workspace/readinessChanged` notifications (`:296-311`). Fixes a bug where `workspace/getStatus` answered `initializing` indefinitely while search worked. `projectClosing` → `unlink(project)` → `refreshReadiness()` derives `DISCONNECTED` when no links. `setState` logs transitions.
4. **Capability gating**: External callers → `isIndexReady()` → if `false`, return `INDEX_NOT_READY` retriable error.
5. **Undo**: `workspace/undo` → `undoable.remove(token)` (one use only) → `IntelliJUndo.undo(project, virtualFile)` on EDT → commit + save → invalidate handles + tracker → `ModificationResult`.

## Common Gotchas
- **Token must never be logged** — the discovery file's token is read and used for handshake, never stored in a serializable field or logged (AGENTS.md §4).
- **`link()` must never be called on the EDT** — discovery file I/O, WebSocket, and handshake are all blocking (BridgeDaemonConnectionService.kt:109-110). The lifecycle listener runs `link` from a `ProjectActivity` which is `suspend` and off-EDT by construction; the tool window dispatches via `executeOnPooledThread`.
- **Serving runs on a dedicated daemon thread** — `RpcClient.serve()` blocks. Running it on the EDT would deadlock when the adapter's own edit needs the dispatch thread. The serving thread is a daemon thread (`isDaemon = true`, `:177`).
- **`disconnectAll()` must be safe from any thread** — `appClosing` may run on the EDT.
- **Old single-connection bug (ADR-0033)** — closing a project killed the serving thread and the daemon dropped the adapter, but the `connected` flag stayed `true`, so `connect()` returned early — **without logging** — and no project ever registered again until the IDE restarted. Readiness reported `DISCONNECTED` while the service believed it was connected. Links are now per project, released when a project closes via `unlink`, and every refusal has a reason.
- **`ReadinessManager` starts in `DISCONNECTED`** — not `INITIALIZING` (ReadinessManager.kt:42). The initial state changes to `INITIALIZING` only when a project opens.
- **`setState` is idempotent** — setting the same state does not log or fire notifications (ReadinessManager.kt:47).
- **`isIndexReady()` returns `true` for `DEGRADED`** — degraded mode still allows index-dependent operations, they just may be slower or partial (ReadinessManager.kt:60).
- **Services are auto-discovered** — do not add XML `<services>` entries in `plugin.xml`; IntelliJ 2025.2 auto-discovers `@Service`-annotated classes (plugin.xml:28-36 comment).
- **`documentRead` reads the in-memory document, not disk** — an editor with unsaved changes is what the user is looking at; answering with saved bytes would hand a consumer text nobody can see (AdapterBackend.kt:260-264).
- **`documentRevision` calls `documentRead`** — computing the revision separately would risk reporting a revision that never described any content the adapter served (AdapterBackend.kt:275-283).
- **Quick fixes are re-resolved at apply time** — the `IntentionAction` is not carried from prepare to apply; between the two phases the document may have changed, and re-resolving from current highlights means a superseded offer is refused rather than applied against text nobody reviewed (AdapterBackend.kt:110-117, 677-690).
- **`applyPlan` saves all documents** — the VS Code adapter writes to disk, and the same protocol operation must not mean "written" on one IDE and "pending in an editor" on another (AdapterBackend.kt:696).
- **`undo` runs on the EDT but not inside a write command** — `UndoManager` opens its own command; nesting one inside ours is rejected by the platform (AdapterBackend.kt:752-760).
- **Undo tokens are one-use** — `undoable.remove(token)` returns null on the second call, which is refused as `PRECONDITION_FAILED`. Undoing twice would revert an edit the consumer never made (AdapterBackend.kt:742-744).
- **`withinWorkspace` filters every result** — the daemon closes the session over a URI outside a registered root, and a hit in a library is not editable anyway (AdapterBackend.kt:555-556).
- **`requestAnalysis` does not block** — analysis is asynchronous; a request that waited would sit against the daemon's route timeout. The snapshot already reports `pending` truthfully (AdapterBackend.kt:300-308).
- **`searchSymbols` warns about unindexed source roots** — a project whose files sit in no source root is indexed for nothing, and no retry will change that. `IndexHealthNotifier.warnNoSourceRoots` is called once per project per session (AdapterBackend.kt:186-187), and the `unindexed` flag also drives `truncated` because the workspace holds matches this response cannot carry (AdapterBackend.kt:252). ADR-0034.
- **`IndexHealthNotifier` is keyed by name and location, not `Project`** — a project that closes and reopens is a different `Project` instance; holding the old one would prevent GC for as long as the IDE runs (IndexHealthNotifier.kt:76).
- **`IntelliJDiagnostics` is the only file using internal API** — `HighlightInfo` is `@ApiStatus.Internal`, baselined in ADR-0027. Everything else is public-API only.
