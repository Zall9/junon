# packages/vscode-extension/

## Responsibility

Development-installable VS Code desktop adapter package for IDEBP. The package now builds autonomous
extension and daemon-child bundles and exercises authenticated adapter registration against the real
loopback daemon. It now serves native in-memory document reads/revisions and projects core document
and workspace-root events. It also serves provider-backed document symbol trees with bounded,
physical-session-bound handles.

## Design

- Unscoped extension name `vscode-extension`; stable ID `ide-bridge.vscode-extension`.
- CommonJS Node 24 bundles generated by pinned esbuild; only `vscode` remains external.
- Workspace extension kind, `onStartupFinished` activation, and limited untrusted-workspace support.
- Settings for local daemon auto-start, private discovery path, authenticated loopback endpoint
  override, log level, and bounded provider timeout. No token or public-listen setting.
- Build checks manifest/entry consistency, residual runtime dependencies, and bundled child loading.

## Flow

VS Code activates `dist/extension.js` → validate configuration/topology → connect through the shared
client → optionally spawn the owned bundled CLI daemon → `ide/register` current workspace state →
attach native document/symbol handlers → restore current state/open documents after daemon rotation →
awaited `ide/unregister`/close/owned-child stop.

## Integration

- Source depends on `vscode`, `@ide-bridge/protocol`, `@ide-bridge/bridge-client`, and the CLI path
  resolver; build-time bundling includes all non-VS Code runtime code.
- Unit/integration tests cover configuration, topology, logging, ownership, schema mapping, real
  registration/unregistration, reconnection, guarded auto-start, native reads, event ordering, and
  daemon scope enforcement, document symbol mapping, handle invalidation, and malicious symbol-result
  rejection.
- Workspace symbol search, navigation, hierarchies, diagnostics with quick-fix offers, two-phase
  edits (rename, reformat, quickFix), trust/rename/delete events, and a real extension-host suite
  (8 scenarios, recording a conformance capture) all landed. The adapter serves 13 of the 16 routed
  methods; the three it does not — `workspace/undo`, `workspace/searchTodos`,
  `workspace/listBookmarks` — are refusals with reasons, because VS Code has no scoped undo, no TODO
  index, and no bookmarks of its own.
